# MCP 服务 stdio → HTTP 改造 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 MCP 服务从 stdio 改为 Streamable HTTP，与 Admin UI 合并为单一常驻 Web 进程（同端口出 `/admin` + `/mcp`），同步修正部署脚本与文档。

**Architecture:** 删除 `Program.cs` 的 stdio 启动路径与三态 `RunMode`，合并为单一 `WebApplication`；MCP 用 `ModelContextProtocol.AspNetCore` 的 HTTP transport 经 `app.MapMcp("/mcp")` 暴露，与 Admin 共享 DI 容器，业务逻辑（`DbQueryTool` / `DbListTool`）零改。部署脚本 `build and install.ps1` 把 Claude MCP 注册从 stdio 改 http、承载（NSSM / 计划任务）由可选变必选。

**Tech Stack:** .NET 8、ASP.NET Core Minimal API、ModelContextProtocol C# SDK（升级到最新稳定）、NSSM / Windows 计划任务、PowerShell 部署脚本。

**Spec:** `doc/20260727-MCP服务改HTTP模式.md`

## Global Constraints

- 仅监听 `IPAddress.Loopback`（127.0.0.1），不暴露局域网（沿用现 `ConfigureKestrel` L87）
- `/mcp` 端点不鉴权（本机信任模型，spec 第 6 节）
- 移除 stdio MCP 模式，后续只保留 HTTP
- `--admin-port` 参数名保留（兼容现有脚本 / 文档）
- MCP session 用 SDK 默认 stateful（不显式开 stateless）
- `ConfigureLogging` 的 `LogToStandardErrorThreshold = Trace` 保留（L300）
- `ShutdownTimeout = 15s` 保留（供 `AuditLogger.DisposeAsync` 排空）
- 业务逻辑零改：`DbQueryTool` / `DbListTool` / `SqlGuard` / `AuditLogger` / `ConfigStore` 等不动
- 数据目录 `%ProgramData%\McpDbTools`（config.json / audit.db / backups）不变
- 部署脚本不加 Codex 自动安装（维持只装 Claude MCP）
- 项目 git：不自动 commit / push / 切分支，每任务末尾 commit 需用户确认（memory `commit-workflow`）
- MCP 模式下 stdout 非协议通道，但日志仍走 stderr（保留现配置）
