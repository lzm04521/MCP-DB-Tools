# 部署脚本 NSSM 旧服务检测 + 提示重装 实施方案

- 日期：2026-07-27
- 状态：实施中
- 范围：`build and install.ps1`

## 目标

脚本检测旧版 NSSM 服务（`AppParameters` 含 `--admin-only`），提示用户重装，刷新服务配置（`AppParameters` / `DisplayName` / `Description`）。

## 背景

HTTP 合一改造后（merge `da26adb`），新版 exe 删了 `--admin-only` 参数解析。旧版 NSSM 服务 `AppParameters` 含 `--admin-only`（被新 exe 忽略，功能无害），但 `DisplayName` / `Description` 仍是旧值。升级旧服务时 `hasExistingNssmService` 路径不刷新配置（最小干预）。本次加检测 + 用户可选重装。

## 检测条件

`hasExistingNssmService` 时，读 `AppParameters`（`nssm get`），查 `--admin-only`。命中即旧服务。

（仅此一条件，最直接。`DisplayName` 旧名不查，因 `--admin-only` 是旧版专属参数。）

## 流程

1. 管理员进程 `hasExistingNssmService` 判定后，读 `AppParameters` 查 `--admin-only`
2. 旧 → `Read-Host "建议重新安装以刷新服务配置...[Y/n]"`（回车默认 Y 重装）
3. **Y → 重装**：`Stop-NssmAdminService` + `nssm remove <service> confirm` + 验证删除 + `Install-NssmAdminService`（新配置）
4. **n → 原路径**（L752 直接 `nssm start`，不碰配置）

## 重装细节

- `Stop-NssmAdminService`（发布前 L675 已停，重装段再 Stop 兜底）
- `nssm remove <service> confirm`（`-IgnoreExitCode`，confirm 非交互确认；nssm 版本差异由 `-IgnoreExitCode` + 验证兜底）
- `Test-WindowsServiceExists` 验证已删除（仍存在则 throw）
- `Install-NssmAdminService`（install + set 新 `AppParameters`/`DisplayName`/`Description` + start）

## 端口

重装沿用现有 `AppParameters` 端口（`--admin-port\s+(\d+)` 解析，含旧 `--admin-only --admin-port N` 子串匹配命中 N），不问。

## 位置

- 检测 + 提示：L624 `hasExistingNssmService` 后（读 `AppParameters` 存 `$existingAppParams`）
- 端口解析：L638 复用 `$existingAppParams`（去重复 `nssm get`）
- 重装执行：L752 启动段，`$needsNssmReinstall` 标志分支
- 输出：L784 重装专属提示

## 风险

- `nssm remove` 删服务，若 remove 失败则 `Install-NssmAdminService` 不执行（验证 throw，用户可手动 install）
- 提权后交互（检测需管理员 `nssm get`，无法在提权前非管理员做）—— 仅此旧服务场景
- `nssm remove confirm` 语法依 nssm 版本（`-IgnoreExitCode` + `Test-WindowsServiceExists` 验证兜底）

## 验证

- PowerShell `Parser::ParseFile` 无语法错
- 实测场景：旧服务（`AppParameters` 含 `--admin-only`）→ 提示 → 重装 → 配置刷新（`AppParameters` 无 `--admin-only`、`DisplayName` 新名）；新服务（无 `--admin-only`）→ 不提示

## 幂等

重装后 `AppParameters` 不再含 `--admin-only`，下次部署检测不命中 → 不提示。
