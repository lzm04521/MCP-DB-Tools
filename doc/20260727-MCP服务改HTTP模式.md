# MCP 服务 stdio → HTTP 改造实施方案

- 日期：2026-07-27
- 状态：待评审
- 范围：`src/McpDbTools.Server` 启动模式、MCP 传输方式、部署脚本、文档同步

## 1. 背景与目标

当前 MCP 服务以 stdio 模式提供：MCP 客户端（Claude Desktop / Claude Code / Codex 等）各自拉起一个子进程，通过 stdin/stdout 通信，每个客户端独立持有进程与配置。部署脚本 `build and install.ps1` 把 MCP（stdio，客户端拉起）与 Admin UI（NSSM / 计划任务常驻 `--admin-only`）作为分离的两个进程部署。

本次目标：

- 改为 HTTP（Streamable HTTP）模式，与 Admin Web 服务共用同一进程、同一端口
- 一个常驻进程同时提供 `/admin`（管理 UI + API）与 `/mcp`（MCP Streamable HTTP）
- 移除 stdio MCP 模式，后续只保留 HTTP
- 部署脚本同步修正，承载（NSSM / 计划任务）由可选变必选
- 解决问题：
  - A. 多 MCP 客户端共享同一服务，不再各自拉起子进程、各自配置
  - B. 部署便利，一个常驻服务统一出 Admin + MCP，便于运维

## 2. 范围

### 本次做

- `Program.cs` 启动路径合并为单一 Web 进程
- MCP 传输从 stdio 改为 Streamable HTTP，端点 `/mcp`
- `RunMode` 枚举与启动参数简化
- csproj 增加 `ModelContextProtocol.AspNetCore` 包引用
- 部署脚本：根目录 `build and install.ps1` 按 HTTP 模式修正（Claude MCP 注册改 HTTP、承载命令行删 `--admin-only`、承载必选化、端口必读）
- 文档同步：项目 `CLAUDE.md`、`README`、Admin UI 内嵌说明（若有）
- 迁移说明：Claude（Claude Code / Claude Desktop）与 Codex CLI

### 本次不做

- 远程访问、网络暴露、TLS（仍仅监听 `127.0.0.1`）
- MCP 端点鉴权（沿用本机信任模型，见第 6 节）
- Windows Service 化（非 NSSM 的原生 sc.exe 服务）、容器化
- 审计来源（session / 调用者）区分
- stateless session 模式优化（本次用 stateful 默认）
- 部署脚本不加 Codex 自动安装（用户决策：维持只装 Claude MCP，Codex 走第 9 节手工迁移说明）

## 3. 架构

改造后单一 `WebApplication` 进程，监听 `127.0.0.1:5123`：

```
单进程 WebApplication (127.0.0.1:5123)
├─ /                → 302 /admin              （现有，保留）
├─ /admin           → Admin UI 静态文件        （现有，保留）
├─ /admin/api/*     → Minimal API             （现有，保留；session cookie Path=/admin）
├─ /admin/session   → 设 cookie               （现有，保留）
└─ /mcp             → MCP Streamable HTTP     （新增；app.MapMcp；不鉴权）
```

MCP 端点与 Admin 共享 DI 容器，`ConfigStore` / `SqlGuard` / `AuditLogger` / `AuditCounter` / `DbQueryTool` / `DbListTool` / `DatabaseProviderFactory` / `QueryConcurrencyLimiter` 全部复用，业务逻辑零改动。

## 4. 代码改动

### 4.1 csproj

增加包引用：

```xml
<PackageReference Include="ModelContextProtocol.AspNetCore" Version="1.4.0" />
```

现有 `<FrameworkReference Include="Microsoft.AspNetCore.App" />` 已存在，AspNetCore MCP 包复用该框架引用。

SDK 1.4.0 的 HTTP transport 方法名实施首步验证：master 分支为 `WithHttpTransport()` + `app.MapMcp()`；1.4.0 时期可能为 `WithStreamableHttpServerTransport()`。若 1.4.0 API 不稳定或缺失，则主包与 AspNetCore 包一同升级至最新稳定版。

### 4.2 Program.cs

入口与启动路径：

- 删除 `RunMcpAsync`（stdio host，L32-67）整段
- 删除 `RunMode` 枚举三态（L345-350）
- 删除 `AdminStartupOptions.Parse` 中的模式分支（L356-360）
- 入口（L21-30）的 `if (Mode == Mcp) RunMcpAsync else RunAdminAsync` 分支删除，直接进入单一 Web 构建路径（可重命名为 `RunAsync`）
- 合并到现 `RunAdminAsync` 骨架，统一使用 `WebApplication.CreateBuilder`，`ConfigureBusinessServices` 从原本两处调用改为一次

MCP 注册：

- 当前 `AdminAndMcp` 模式条件块（L89-95）的 MCP 注册移出，改为无条件注册
- stdio transport `WithStdioServerTransport()` 改为 HTTP transport（`WithHttpTransport()` 或 1.4.0 等价），保留 `.WithToolsFromAssembly()`
- 新增 `app.MapMcp("/mcp")`，与现有 `/admin`、`/admin/api`、静态文件路由并列

服务注册：

- `AdminConfigService`（L79）、`MaintenanceHostedService`（L81）随合并始终注册（不再依赖模式分支）

参数：

- 删除 `--admin-only`、`--admin`
- 保留 `--admin-port`（兼容现有启动脚本与文档）；命名虽不再准确（端口同时服务 MCP），但改名需同步启动脚本，本次保留，spec 注明

日志：

- `ConfigureLogging` 的 `LogToStandardErrorThreshold = Trace`（L300）原为 stdio stdout 协议约束。HTTP 模式下 stdout 不再是协议通道，约束失效，但保留无害，倾向保留以减少改动

关闭与审计排空：

- 保留 `ShutdownTimeout = 15s`（L46）配置，确保 host 关闭时 `AuditLogger.DisposeAsync` 排空审计队列
- 删除自定义 `CancelKeyPress` 处理（L52-57），`WebApplication` 内置 Ctrl+C / SIGTERM 处理

### 4.3 业务代码

`DbQueryTool` / `DbListTool` 业务逻辑零改动。

HTTP 模式下 `CancellationToken` 来自 `HttpContext.RequestAborted`（由 SDK 传入工具方法），`DbQueryTool.ExecuteQuery` 已正确接收并传递（L47 default、L86 使用），无需改。

## 5. MCP transport 配置

- 采用 **stateful 模式（SDK 默认）**。理由：
  - 文档明确 stateful 为 "Full MCP protocol support"，stateless 缺 client sampling / roots 等能力
  - `db_query` / `db_list` 虽无状态，但本机单客户端场景 session 开销可忽略
  - 默认模式最稳，避免 stateless 协议边界风险
- stateful 模式下，SDK `WithHttpTransport()` 自动注册 `IdleTrackingBackgroundService`，负责清理空闲 session，无需额外处理
- 工具实例由 DI Singleton 提供，跨 session 共享 `ConfigStore` / `AuditLogger` / `QueryConcurrencyLimiter`，行为与 stdio 现状一致
- stateless 模式列为后续可选优化（水平扩展场景），本次不做

## 6. 鉴权与安全边界

- `/mcp` 端点 **不鉴权**。任何能访问 `127.0.0.1:5123/mcp` 的本机进程或用户均可调用 `db_query` 查询全部配置数据库
- 与当前 Admin `/admin/api` 的实际安全级别一致：Admin 的 session cookie（Path=/admin）主要防浏览器 CSRF，对能发 HTTP 请求的本机进程无防护（cookie 在首次访问 `/admin` 时即自动下发，L100-107）
- 缓解：仅监听 `IPAddress.Loopback`（沿用 L87 `ConfigureKestrel`），不暴露局域网与外部网络
- **风险扩大点**：相比 stdio，HTTP 模式威胁面扩大——
  - stdio 模式下，攻击需启动本程序二进制（隐含执行权限与协议私有性）
  - HTTP 模式下，`/mcp` 为标准 HTTP endpoint，本机任意进程 `curl` 即可调用
- **同机多用户**：Windows 上 `127.0.0.1` 不跨用户隔离，同机其他用户进程亦可连接 `127.0.0.1:5123/mcp`
- 远程访问、TLS、端点鉴权留后续独立设计，本次明确不做，spec 显式记录此风险

## 7. 审计

- 沿用现有 `AuditLogger`，HTTP 多 session 共享，不区分调用者
- HTTP 模式下 `HttpContext` 可获取来源信息（remote IP、session id），后续若需来源区分可扩展审计字段，本次不做

## 8. 部署与常驻

- HTTP 模式要求服务常驻在线，MCP 客户端依赖该进程持续运行
- 相比 stdio（客户端自动拉起子进程），HTTP 模式失去自动拉起优势；服务未运行时客户端连接失败
- 本次 **不** 引入 Windows Service（sc.exe 原生服务）/ 容器化方案

### 常驻方式（已确认）

- 当前 `--admin-only` 进程通过 **NSSM 服务** 或 **登录计划任务** 常驻（用户确认，二者择一，部署脚本自动探测 nssm，无则回退计划任务）
- HTTP 模式沿用同一套机制：NSSM 服务（LocalSystem，开机自启）或登录计划任务（当前用户，登录自启）
- 承载由原"可选"变"**必选**"：HTTP 模式无 stdio 兜底，不部署承载则 MCP 客户端无服务可连。部署脚本相应调整（见第 12 节）

## 9. 迁移说明

stdio 模式移除后，现有 MCP 客户端的 stdio command 配置全部失效，需改为 HTTP URL 配置：`http://127.0.0.1:5123/mcp`。

本次文档只覆盖 **Claude** 与 **Codex** 两种客户端。

### Claude（Claude Code / Claude Desktop）

- Claude Code：`claude mcp add -s <scope> -t http <name> http://127.0.0.1:5123/mcp`（语法已核对 `claude mcp add --help`，`-t http <name> <url>`）
- Claude Desktop：`claude_desktop_config.json` 的 `mcpServers` 条目由 `command` + `args` 改为 `url` 字段形式

### Codex（Codex CLI）

- `~/.codex/config.toml` 的 `[mcp_servers.xxx]` 由 stdio command 形式改为 HTTP URL 形式，指向 `http://127.0.0.1:5123/mcp`
- 部署脚本 **不** 自动安装 Codex（第 2 节范围决策），手工配置

具体字段名实施时按客户端当前版本文档核对，spec 不写死易变字段名。

## 10. 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| SDK 1.4.0 HTTP API 未最终确认 | 本地 `ModelContextProtocol.AspNetCore` 包未下载，1.4.0 方法名待验证 | 实施首步验证；必要时主包 + AspNetCore 包升最新稳定 |
| 客户端版本兼容 | Claude / Codex 客户端需支持 Streamable HTTP | 2025+ 版本均支持；迁移前确认客户端版本 |
| 不鉴权威胁面扩大 | 本机任意进程可调 `/mcp` | 仅 `127.0.0.1`；同机信任模型；远程/鉴权留后续 |
| 同机多用户 | Windows `127.0.0.1` 不跨用户隔离 | 纳入风险记录；多用户场景需后续鉴权设计 |
| 服务常驻依赖 | HTTP 须在线，失去 stdio 自动拉起 | 脚本强制 NSSM/计划任务（第 12 节）；部署后确认服务起 |
| stateful idle session | 空闲 session 占内存 | SDK `IdleTrackingBackgroundService` 自动清理 |
| 发布组合冒烟 | `PublishSingleFile` + `SelfContained` + Kestrel + MCP HTTP | 发布版实测（见第 11 节） |
| 现有 stdio 用户配置迁移 | 全量改 HTTP URL | 迁移说明（第 9 节）+ 脚本自动改 Claude |
| 脚本承载必选化行为变化 | 旧版"跳过承载"路径消失 | 脚本无 nssm 时强制计划任务；部署计划明示 |
